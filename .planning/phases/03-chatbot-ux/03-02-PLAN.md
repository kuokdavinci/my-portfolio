       ```javascript
       function updateAgentState(thinkingMessage, completedStepId) {
         if (!thinkingMessage || !thinkingMessage.parentNode) return;
         
         const steps = thinkingMessage.querySelectorAll('.agent-state-step');
         let foundCompleted = false;
         
         steps.forEach(stepEl => {
           const stepId = stepEl.dataset.step;
           const statusEl = stepEl.querySelector('.state-status');
           const iconEl = stepEl.querySelector('.state-icon');
           
           if (foundCompleted || stepId === completedStepId) {
             // Mark this step as completed
             stepEl.dataset.status = 'completed';
             stepEl.classList.remove('state-pending', 'state-active');
             stepEl.classList.add('state-completed');
             if (statusEl) statusEl.innerHTML = '<span class="material-symbols-outlined state-check" style="color: var(--color-success, #4caf50); font-size: 18px;">check_circle</span>';
             if (iconEl) iconEl.style.color = 'var(--color-success, #4caf50)';
             foundCompleted = true;
           } else if (!foundCompleted) {
             // Mark as active (current step)
             stepEl.dataset.status = 'active';
             stepEl.classList.remove('state-pending', 'state-completed');
             stepEl.classList.add('state-active');
           }
           // Steps after the completed one remain pending
         });
       }
       ```

    **Problem:** The current click handler on messages calls `closeChat()` when clicking internal links (#section). This forces users to re-open the chat after exploring a referenced section. External links already open in new tabs but the chat still closes if the link has a # href.

    **Fix:** Remove the `closeChat()` call from the link click handler. Internal links should navigate in the background, external links should open in new tabs — neither should close the chat.

    1. **Replace the current click handler** (lines 303-308) with:
       ```javascript
       messages.addEventListener('click', (e) => {
         const link = e.target.closest('a');
         if (!link) return;
         
         const href = link.getAttribute('href');
         if (!href) return;
         
         if (href.startsWith('#')) {
           // Internal link: scroll to section without closing chat
           e.preventDefault();
           const targetId = href.substring(1);
           const targetElement = document.getElementById(targetId);
           if (targetElement) {
             targetElement.scrollIntoView({ behavior: 'smooth', block: 'start' });
           }
         }
         // External links: already have target="_blank" from parseMarkdown, no action needed
         // Chat stays open in both cases
       });
       ```

    2. **Ensure all links have proper attributes** — Verify that `parseMarkdown()` (line 27-31) and source link rendering (lines 96-102, 148-155) already set:
       - External links: `target="_blank" rel="noopener"` (already done in parseMarkdown)
       - Internal links: no target attribute (already done)
       
       If any link rendering is missing `rel="noopener"` on external links, add it.

    3. **Add visual feedback** — Add a subtle hover indicator to links so users know they're clickable:
       In `src/style.css`, add within `@layer components`:
       ```css
       .rag-chat-bubble a {
         cursor: pointer;
         transition: opacity 0.15s ease;
       }
       
       .rag-chat-bubble a:hover {
         opacity: 0.8;
       }
       ```

    4. **DO NOT** change the `closeChat()` function itself — it's still used by the close button and should work normally. Only remove its call from the link click handler.

    **Why this works:** By calling `e.preventDefault()` on internal links and manually scrolling to the target, we bypass the default hash navigation (which could cause issues) while keeping the chat open. External links open in new tabs via `target="_blank"`, which doesn't affect the current page or chat state.
