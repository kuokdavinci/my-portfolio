**Backend SSE Endpoint (add to backend/main.py):**
```python
from fastapi.responses import StreamingResponse
import asyncio
import json
from collections import deque

# In-memory request log (last 100 requests)
request_log = deque(maxlen=100)
sse_clients = set()

@app.get("/api/v1/stream")
async def request_stream():
    async def event_generator():
        client_queue = asyncio.Queue()
        sse_clients.add(client_queue)
        try:
            # Send existing log first
            for entry in request_log:
                yield f"data: {json.dumps(entry)}\n\n"
            # Then stream new events
            while True:
                entry = await client_queue.get()
                yield f"data: {json.dumps(entry)}\n\n"
        finally:
            sse_clients.discard(client_queue)
    return StreamingResponse(event_generator(), media_type="text/event-stream")

# In prometheus_middleware, after processing each request:
async def prometheus_middleware(request, call_next):
    # ... existing code ...
    # Add to request log
    entry = {
        "timestamp": datetime.utcnow().strftime("%H:%M:%S"),
        "method": method,
        "path": endpoint,
        "status": status_code,
        "duration_ms": round(duration * 1000)
    }
    request_log.append(entry)
    # Broadcast to SSE clients
    for client_queue in sse_clients:
        await client_queue.put(entry)
    return response
```

**Frontend SSE Connection:**
```javascript
function initLiveStream(container) {
  const eventSource = new EventSource('http://localhost:8000/api/v1/stream');
  const logContainer = container.querySelector('.live-stream-log');

  eventSource.onmessage = (event) => {
    const entry = JSON.parse(event.data);
    const line = document.createElement('div');
    line.className = `log-entry status-${Math.floor(entry.status / 100) * 100}`;
    line.textContent = `[${entry.timestamp}] ${entry.method} ${entry.path} ${entry.status} ${entry.duration_ms}ms`;
    logContainer.appendChild(line);

    // Keep max 100 rows
    while (logContainer.children.length > 100) {
      logContainer.removeChild(logContainer.firstChild);
    }

    // Auto-scroll
    logContainer.scrollTop = logContainer.scrollHeight;
  };

  eventSource.onerror = () => {
    // SSE will auto-reconnect
  };

  return eventSource;
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SSE stream → Browser | Real-time request data exposed to any visitor |
| Error rate display → User perception | Error rates could reveal system instability |
| Container metrics → Host | cAdvisor reads host filesystem (read-only) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05.3-01 | Information Disclosure | SSE request stream | mitigate | Only expose method, path, status, duration — no request/response bodies, no query params, no session IDs |
| T-05.3-02 | Denial of Service | SSE client queue growth | mitigate | Use deque with maxlen=100 for request_log, limit SSE clients to 10 concurrent connections, drop events if queue full |
| T-05.3-03 | Information Disclosure | Error rates visible to visitors | accept | Error rates are aggregate percentages, no stack traces or error messages exposed, low sensitivity for portfolio context |
| T-05.3-04 | Elevation of Privilege | cAdvisor container access | mitigate | Read-only mounts, non-root container, no write access to host |
</threat_model>
