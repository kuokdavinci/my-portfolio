Create `src/modules/tracking/tracker.js` — an enhanced tracking SDK that replaces the current inline `trackEvent()` function in main.js.

Features:
1. **Batched events:** Queue events and flush every 5s or when queue reaches 10 items
2. **Retry queue:** Failed sends are retried up to 3 times with exponential backoff
3. **Beacon API fallback:** If fetch fails, use navigator.sendBeacon() for critical events
4. **Session lifecycle:** Track session_start on init, session_end on page unload (via beacon)
5. **Heartbeat:** Send heartbeat every 30s to update active_sessions gauge
6. **Event types:** page_view, session_start, session_end, scroll_depth, resume_download, project_click, chat_query, time_spent

Export a `Tracker` class with methods:
- `init()` — Start session, set up heartbeat interval, bind unload handler
- `track(eventType, payload)` — Queue event for batched send
- `flush()` — Send queued events to /api/v1/track
- `startHeartbeat()` — POST /api/v1/heartbeat every 30s
- `destroy()` — Clear intervals, send final events via beacon

Update main.js to import and use the new Tracker instead of inline trackEvent(). Keep backward compatibility — the global trackEvent() function should delegate to Tracker.track().

Also add scroll depth tracking at 25%, 50%, 75%, 100% levels (currently only 50% and 90%).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → /api/v1/track | Untrusted event data from browser |
| Client → /api/v1/heartbeat | Session ID could be spoofed |
| Client → /metrics | Prometheus endpoint exposed (read-only, low risk) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05.1-01 | Tampering | /api/v1/track endpoint | mitigate | Validate TrackingEvent schema with Pydantic, reject malformed payloads, rate limit per session_id |
| T-05.1-02 | Information Disclosure | /metrics endpoint | accept | No PII in metrics, all counters/aggregates only, low-value target for attacker |
| T-05.1-03 | Spoofing | Session ID in tracking events | mitigate | Generate server-side session ID on first visit, validate format (UUID-like pattern) |
| T-05.1-04 | Denial of Service | /api/v1/heartbeat flood | mitigate | Rate limit heartbeat to 1 per 30s per session, drop excess requests |
</threat_model>
